# TechnoElevate Proof Pack

Use this folder before sales meetings, RFPs, or when a prospect asks *"Can you prove what's on your website?"*

## Folder structure

```
proof-pack/
├── README.md                    ← Start here
├── SITE-CLAIMS-AUDIT.md         ← Every website claim + status
├── PROOF-GAPS-ACTION-PLAN.md    ← Priority fixes (website + internal)
├── PROJECT-REGISTER.csv         ← Master list of all projects (fill in)
├── CLIENT-REFERENCE-MATRIX.csv  ← Logo / reference / NDA tracking
├── CASE-STUDY-CHECKLIST.md      ← Per-project proof checklist
└── evidence/                    ← Drop PDFs here (create subfolders per client)
    ├── 01-company/
    ├── 02-certifications/
    ├── 03-case-studies/
    ├── 04-testimonials/
    └── 05-security/
```

## Golden rule

**If it is on the website, it must exist in this folder — or the website wording must change.**

## Quick prep before a client call (30 min)

1. Open `SITE-CLAIMS-AUDIT.md` — know which claims are 🔴 Needs proof
2. Pull Tier A case folders from `evidence/03-case-studies/`
3. Have CMMI cert PDF in `evidence/02-certifications/`
4. Confirm logo rights in `CLIENT-REFERENCE-MATRIX.csv`
5. Never cite a metric not backed by a row in `PROJECT-REGISTER.csv`

## Status legend (used in audit)

| Status | Meaning |
|--------|---------|
| ✅ Verified | Proof on file; safe to state publicly |
| 🟡 Qualified | True with definition/context; soften website copy |
| 🔴 Needs proof | No evidence yet — do not use in live pitches |
| ⚠️ Soften | Change website wording immediately |

## Owner

Assign one **Proof Pack Owner** (Delivery Lead or Sales Ops) to update the CSV files when projects close.
