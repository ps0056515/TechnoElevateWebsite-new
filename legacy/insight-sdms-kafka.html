Zero-Downtime Monolith Breakup with Kafka Event Sourcing

10 min read · Manufacturing · By TechnoElevate Engineering

Dalmia Bharat Cement's Sales Discount Management System (SDMS) was a Java 8 monolith buckling under its own weight: a 3,000-thread pool masking database bottlenecks, a God Object with 80+ fields, and brittle SAP HANA integration. Dealer rebate schemes across 18+ types needed horizontal scale — the monolith couldn't deliver.

Strangler fig with event sourcing

TechnoElevate designed a monolith-to-microservices transformation using Domain-Driven Design (DDD), Kafka-driven event sourcing and a Kubernetes-native stateless calculation engine. The strangler fig pattern let us migrate scheme types incrementally — maintaining zero downtime throughout production operation.

Decoupling SAP HANA integration

The SAP HANA integration was the most fragile coupling in the monolith. Event-driven boundaries isolate SAP sync from discount calculation logic — failures in one domain no longer cascade. Resilient retry and dead-letter handling replaced brittle synchronous calls.

Outcomes

Horizontal scaling of the discount calculation engine, elimination of DB thread-pool bottlenecks, and a validated zero-downtime migration path that other manufacturing clients can replicate. See also our delivery methodology for how we structure these migrations.
